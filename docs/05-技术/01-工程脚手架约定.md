```
LiarBar/                          ← DevEco 工程根（尚未创建）

│   └── app.json5
├── entry/

│       │   ├── features/         按玩法切片（非按控件切片）
│       │   │   ├── lobby/        F-01 开桌
│       │   │   ├── table/        对局桌、看牌、出牌包
│       │   │   ├── challenge/    F-05 三拍
│       │   │   ├── spectator/    F-06 旁观
│       │   │   ├── recap/        F-10 战报
│       │   │   └── tutorial/     F-12 教学
│       │   ├── engine/           规则状态机（纯逻辑，无 UI）
│       │   ├── ai/               荷官 + 三人格牌友（读配置表）
│       │   ├── config/           读 JSON；禁止在此写死规则数
│       │   ├── persist/          本地昵称 / 战绩 / 上次开桌配置
│       │   ├── harmony/          防窥 / 实况窗 / 智能填充 适配层
│       │   └── common/           枚举、日志事件、工具
│       └── resources/
│           ├── base/element/     字符串、色、浮点（手感阈值也可进 JSON）
│           ├── base/media/       牌面/UI 占位图
│           └── rawfile/config/   ★ 数值表 JSON（见 §3）
└── docs/                         本仓库文档（已存在；工程创建后勿复制进 HAP）
```

| 目录 | 职责 | 禁止 |
|------|------|------|
| `engine/` | 阶段转移、质疑判定、§10.1 | 调 UI、读窗口、调鸿蒙 Kit |
| `ai/` | 读人格概率表决策 | LLM 判真假/胜负 |
| `harmony/` | Kit 封装，失败可降级 | 把 Kit 调用散落到页面 |
| `config/` | 加载/校验 JSON | `if (lives === 3)` 写死 |
| `features/*` | 页面与交互 | 复制一份判定函数 |

**MVP 本地人机数据流**（约定，非实现）：

```
UI(features) ──意图──► engine ──快照──► UI
                 │
                 ├── ai（座位 role=AI 时）
                 ├── config（只读表）
                 └── persist（局后战绩；对局中不改规则）
```

荷官是 `engine` 的推进器 + 模板播报，不是独立服务器。

## 3. 配置表接入（JSON 化草案）

**原则（与数值文档一致）**：所有数进配置表；试玩只调表；锁定键改前过制作人。

### 3.1 文件建议

| 路径（开工后） | 内容 | 热更？ |
|----------------|------|--------|
| `resources/rawfile/config/match_defaults.json` | §3.2 对局基础 + 超时 | MVP 打进包 |
| `resources/rawfile/config/deck.json` | 牌堆构成、宣称集合 | 打进包 |
| `resources/rawfile/config/ai_personas.json` | 三人格概率 | 打进包 |
| `resources/rawfile/config/interaction_caps.json` | 敲桌/画✗ 等上限 | 打进包 |
| `resources/rawfile/config/demo_seed.json` | 演示种子开关与剧本钩子 | 打进包 |

开局时 **深拷贝进 `Match.config`**，本局内不再读文件（避免中途改表造成裁定漂移）。

### 3.2 键名（必须与数值文档一致）

下列键名 **逐字对齐** [数值与牌堆配置](../02-游戏设计/数值与牌堆配置.md)，禁止别名（如不要把 `lives_default` 写成 `hp`）。

```json
{
  "schema_version": "0.2",
  "min_players": 3,
  "max_players": 6,
  "default_players": 4,
  "lives_default": 3,
  "hand_size_default": 5,
  "max_play_cards": 3,
  "min_play_cards": 1,
  "turn_seconds": 15,
  "challenge_only_seconds": 8,
  "challenge_bet_seconds": 2,
  "challenge_ritual_max_seconds": 4,
  "low_time_threshold": 5,
  "timeout_auto_play": true,
  "max_slam_per_game": 5,
  "max_hesitate_per_game": 8,
  "hesitate_dwell_ms": 800,
  "soft_max_velocity": 1200,
  "slam_min_velocity": 2800,
  "demo_seed_enabled": true,
  "demo_seed_value": 20260906,
  "avoid_same_claim_streak": 1,
  "face_bet_enabled": true,
  "face_bet_correct": 2,
  "face_bet_wrong": 0,
  "auto_play_prefer_legal": true,
  "auto_play_else": "random_one",
  "challenge_only_on_timeout": "skip",
  "consecutive_timeout_warn": 2,
  "ai_think_ms_min": 400,
  "ai_think_ms_max": 1200
}
```

| 键 | 锁定？ | 程序禁区 |
|----|--------|----------|
| `lives_default` `hand_size_default` `min_play_cards` `max_play_cards` | **锁定** | 不得为「手感」私自改默认 |
| `challenge_only_seconds` | **锁定 8** | 不得改成回合 15s 混用 |
| `face_bet_enabled` / `face_bet_wrong` | **锁定** 开 / 0 | 押错不得扣分 |
| `demo_seed_enabled` / `demo_seed_value` | 默认 true / `20260906` | 演示包保持开启 |
| `turn_seconds`、Joker 张数、AI 概率 | 可试玩调表 | 只改 JSON |

### 3.3 牌堆 JSON 草案

```json
{
  "ranks": ["A", "K", "Q"],
  "wild": "JOKER",
  "claimable": ["A", "K", "Q"],
  "decks": {
    "3": { "A": 6, "K": 6, "Q": 6, "JOKER": 3 },
    "4": { "A": 8, "K": 8, "Q": 8, "JOKER": 4 },
    "5": { "A": 10, "K": 10, "Q": 10, "JOKER": 5 },
    "6": { "A": 12, "K": 12, "Q": 12, "JOKER": 6 }
  }
}
```

- `claimable` **不含** `JOKER`（G-Q7）。  
- 5～6 人桌为 P1；MVP 主路径读 `"4"`。  
- 重建发牌（GDD §10.1）：对**存活**座位按 `hand_size_default` 从 **完整** `decks[n]` 洗牌重发，不是从弃牌堆抽。

### 3.4 判定公式（只实现数值文档，不改语义）

```
is_legal(card, claim)      = card.rank == claim OR card.rank == JOKER
hand_is_clean(cards, claim)= 每张 is_legal
质疑成功                   ⇔ NOT hand_is_clean(上家本手, claim)
```

实现必须放 `engine/`，单测对着这三行；禁止 UI 层重写。

### 3.5 魔法数禁令（验收可勾）

- [ ] `entry/src` 内无 `15`/`8`/`3`/`5` 作为规则常量（枚举下标、数组长度除外）  
- [ ] 超时、命数、手牌、出牌张数、仪式秒数均来自 `Match.config`  
- [ ] SOFT/SLAM/HESITATE 阈值读 `soft_max_velocity` / `slam_min_velocity` / `hesitate_dwell_ms`  
- [ ] 新增键先改数值文档再改 JSON，禁止只改代码

## 4. 资源命名占位（给 UI / 美术的接口）

先锁 **前缀 + 组件态**，不锁最终切图。美术出图时按「前缀_语义_态」补文件即可，程序不改枚举。

### 4.1 全局前缀

| 前缀 | 用途 | 示例（占位） |
|------|------|--------------|
| `lb_card_` | 牌背/牌面 | `lb_card_back_default` `lb_card_face_a` `lb_card_face_joker` |
| `lb_seat_` | 头像框、命、出局 | `lb_seat_life_on` `lb_seat_ghost` |
| `lb_claim_` | 宣称条 | `lb_claim_rank_a` |
| `lb_ui_` | 桌面铬合金（按钮、倒计时） | `lb_ui_btn_play` `lb_ui_timer` |
| `lb_fx_` | 质疑/惩罚特效 | `lb_fx_flip` `lb_fx_penalty` |
| `lb_emote_` | 表情符号面具 | `lb_emote_smile`（对齐互动方案枚举） |
| `lb_sfx_` | 音效 | `lb_sfx_knock` `lb_sfx_slam` |
| `lb_str_` | 字符串 | `lb_str_claim_announce` |
| `lb_color_` | 色板 | `lb_color_tavern_bg` |

皮肤：默认「夜半酒馆」走 `base/`；校园皮「食堂饭卡局」日后加 `resources/dark` 或 qualifier，**文件名不改**。

### 4.2 组件态 vs 资源名（先给可扩展接口）

程序认 **组件态枚举**；态 → 资源名由一张映射表完成，禁止在组件里拼文件名散落。

| 组件 | 态（逻辑） | 资源键（占位） | 说明 |
|------|------------|----------------|------|
| `HandCard` | `BACK` | `lb_card_back_default` | 默认不可见牌面 |
| `HandCard` | `PEEK` | `lb_card_face_{rank}` | 仅长按；同时开防窥（F-03） |
| `HandCard` | `SELECTED` | `lb_card_face_{rank}` + `lb_ui_card_selected` | 出牌多选 |
| `HandCard` | `DISABLED` | 同 BACK + 降透明度 | 张数超 `max_play_cards` 等 |
| `ChallengeBtn` | `HIDDEN` | — | 非 TURN 或自己未行动 |
| `ChallengeBtn` | `ENABLED` | `lb_ui_btn_challenge` | `canChallenge==true` |
| `ChallengeBtn` | `DISABLED_FIRST_PLAY` | `lb_ui_btn_challenge_off` | **本轮第一手** |
| `ChallengeBtn` | `DISABLED_NO_TARGET` | 同上 | 无上家本手 |
| `ChallengeBtn` | `CHALLENGE_ONLY` | `lb_ui_btn_challenge_only` | 无牌仅质疑窗 |
| `PlayStyleHint` | `SOFT` / `SLAM` / `HESITATE` | `lb_fx_soft` / `lb_fx_slam` / `lb_fx_hesitate` | 互动方案 §3.3.1 |
| `LiveCapsule` | `YOUR_TURN` / `CHALLENGE_CD` / `FLIPPING` | 实况窗文案走 `lb_str_live_*` | 见 `03`；**禁止**把牌面塞进实况窗 |
| `EmoteMask` | `SMILE` `SMIRK` `FROWN` `BROW_UP` `AVERT` `STARE_NOD` `PANIC` | `lb_emote_{enum}` | FaceAR 与轮盘同一空间 |

未出图时用纯色矩形 + `lb_str_` 字，**态枚举仍要留**，避免日后改逻辑。

## 5. 分支 / 目录约定（与制作人工作流一致）

摘自 [02-制作人工作流与验收](../00-立项/02-制作人工作流与验收.md)，客户端补充如下：

| 前缀 | 用途 | 本岗示例 |
|------|------|----------|
| `feat/design-*` | 玩法文档 | 不由客户端开 |
| `feat/art-*` | 美术 | 不由客户端开 |
| **`feat/client-*`** | 客户端约定与日后实现 | **本批：`feat/client-tech-spec`**（仅 docs） |
| `feat/server-*` | 服务端 | MVP 不开（无人机联网） |
| `feat/test-*` | 用例/试玩 | 状态机单测日后用 |

| 约定 | 说明 |
|------|------|
| 文档 PR 标题 | `docs:` / `docs(client):` |
| 合入目标 | 当前文档流走 **`develop`**；**禁止**把未审内容直接合 `main` |
| 本批范围 | 只改 `docs/05-技术/` + 文档中心导航；**不改** GDD/PRD/数值规则正文 |
| 实现开工后 | 一特性一分支，例如 `feat/client-turn-ui`、`feat/client-privacy-peek` |
| 忽略规则 | 工程文件的忽略写在本地 exclude；密钥不进库（日后若有） |

```
读一页纸 → GDD → 数值 → PRD → 本目录
  → feat/client-* 产出
  → PR（写清对齐哪条决议）
  → 制作人审核 → 合格再给下游实现
```
