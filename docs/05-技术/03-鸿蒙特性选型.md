## 2. P0-1 隐私防窥（F-03）

### 2.1 服务哪条玩法

GDD 支柱「信息差」：牌私有、表演公开。长按揭牌 + 揭开瞬间防窥，避免室友侧目直接读牌——这是骗子酒吧能在手机上成立的前提，不是装饰。

| 绑定 | 内容 |
|------|------|
| PRD | F-03 长按看牌 + 防窥 |
| GDD | §3.4 手牌私密性；教学 §11 步骤 2 |
| 状态机 | 仅看牌叠层为揭牌；`JUDGE` 翻的是上家本手公开牌，**不走防窥** |
| 控件 id | `lb_scr_peek` · `lb_cmp_peek_mask` · `lb_cmp_card_{0-4}` · **`lb_privacy_on`** |
| 媒体 `$r` | `art_card_*` · `art_card_privacy_mask`（**禁止 `lb_art_*`**） |

### 2.2 演示怎么讲（30 秒）

1. 竖握手机，对评委说：「手牌默认牌背。」  
2. 长按自己手牌：正面出现；请邻座/第二机 **侧 45° 拍** 或试系统截屏。  
3. 松手：牌收回。旁白：「防窥跟看牌绑定，不是全局模糊——全桌仍看得出我在看牌、我的表情，只是看不清点数。」  
4. 可选对比：关防窥的录屏对照（调试开关，正式包默认关）。

### 2.3 实现要点（选型级）

| 要点 | 约定 |
|------|------|
| 触发 | `lb_cmp_card_*` 长按进入 `lb_scr_peek` → 调用 **`lb_privacy_on`**；松开 / 进后台 / 关遮罩 → 关 |
| 系统能力 | 窗口隐私模式（如 `window.setWindowPrivacyMode`）防截屏/录屏进图库；能开隐私护盾/防窥显示的机型再叠一层视角变暗 |
| 与 UI | 松手回 `$r` `art_card_back`；防窥失败也必须能看牌（降级：仅本机可见 + 截屏警告 toast） |
| 日志 | 可记 `PEEK_START/END`，**不写 rank** |

### 2.4 不做清单

- 不对整个对局桌常开防窥（旁观要看见甩出/质疑仪式）  
- 不在实况窗、战报、互动卡片里放手牌正面  
- 不做「侦测旁边人脸就自动扣牌」的摄像头方案（拒摄像头仍须完整可玩）  
- 不把防窥当反作弊（防的是社交窥视，不是外挂）

### 2.5 验收一句

> **长按看牌期间防窥开启，松手关闭；侧拍或系统截屏看不到手牌正面，对局其余公开动画不受影响。**

## 3. P0-2 实况窗（F-08）

### 3.1 服务哪条玩法

回合有钟、质疑有窗。评委锁屏后仍能看见「轮到谁 / 还剩几秒 / 本轮出什么」——把「靠吼推进」换成系统级倒计时，并在答辩时 10 秒证明「用了鸿蒙实况窗」。

| 绑定 | 内容 |
|------|------|
| PRD | F-08 回合倒计时 + 实况窗 |
| GDD | §9.2 同步字段；互动方案「系统节奏层」 |
| 状态机 | 订阅 `phase` + 当前窗剩余秒 + `currentClaim.rank` |
| 控件 id | 桌内同源：`lb_cmp_topbar` · `lb_txt_timer` · `lb_txt_claim`；质疑中切 `lb_challenge_windup` → `lb_challenge_standoff` → `lb_challenge_reveal` → `lb_challenge_result` |

### 3.2 演示怎么讲（30 秒）

1. 对局进入 `TURN`（最好轮到真人）。  
2. 上滑锁屏或按电源（勿杀进程）。  
3. 指状态栏/锁屏实况窗：「轮到你出牌 · 宣称 A · 12s」。  
4. 等秒数跳变或切到质疑：「翻牌中」。解锁回桌，阶段一致。  
5. 旁白：「人机全本地更新，不靠推送服务器。」

### 3.3 实现要点（选型级）

| 要点 | 约定 |
|------|------|
| Kit | Live View Kit（`@kit.LiveViewKit` / `liveViewManager`）：`startLiveView` → 阶段变化 `updateLiveView` → `RECAP`/`END`/`LOBBY` 时 `stopLiveView` |
| 字段（仅此三项进胶囊） | ① 阶段文案 ② 剩余整秒 ③ 宣称简称（如「出 A」） |
| 更新节流 | 秒级即可；`TURN`/`CHALLENGE_ONLY` 用对应时限键 |
| 进程 | MVP **端侧本地**创建/更新；**不**接 Push Kit 云更（与「只人机本地」一致） |
| 课设风险 | 上架要实况窗权益；答辩用调试机/白名单。无权益则桌内倒计时仍必须在，实况窗标「降级」 |

阶段文案建议（策划可改字；**勿另造**与 UI 表冲突的 `lb_str_*`。宣称桌内用已有 `lb_str_claim_fmt`「本轮出 {rank}」）：

| 阶段/窗 | 文案草案 | 桌内对照 |
|---------|----------|----------|
| `TURN` + `NORMAL` 且是自己 | 轮到你出牌 | `lb_txt_timer` |
| `TURN` + `NORMAL` 且是别人 | 等待 {昵称} | 座位 `_turn` |
| `TURN` + `CHALLENGE_ONLY` | 可质疑 · 仅此窗 | `lb_str_hand_empty` |
| `PLAY_REVEAL_SELF` | 确认出牌 | `lb_scr_play` |
| `lb_challenge_windup` | 起势 | `lb_cover_challenge` |
| `lb_challenge_standoff` | 对峙 / 押注倒计时 | `lb_cmp_bet_bar`（独立拍，不并进 reveal） |
| `lb_challenge_reveal` | 翻牌中 | `lb_cmp_reveal_row` |
| `lb_challenge_result` / `JUDGE` | 定格 | 只示意输赢 |
| `PENALTY` | 结算命数 | `art_fx_wine_splash` |
| `CLAIM` / `DEAL` | 新一轮 | `lb_txt_claim` |

### 3.4 不做清单

- 实况窗 **禁止**展示手牌、本手牌面、AI 概率  
- 不做点击实况窗「代出牌/代质疑」（锁屏只看，操作回前台）  
- 不做跨设备流转实况窗（见 §6 不选接续）  
- 不把实况窗当联网对局的同步通道  

### 3.5 验收一句

> **锁屏或熄屏时可见阶段文案、剩余秒数、宣称简称，且与桌内倒计时一致；窗内无任何牌面。**

## 4. P0-3 智能填充（F-11）

### 4.1 服务哪条玩法

一页纸场景是课间/宿舍 30 秒能开打。MVP 无账号，但不能每次重打昵称和 4 人 3 命。智能填充 = 系统级昵称建议 + 本地「常用桌」一键填，服务 F-01，不是独立小游戏。

| 绑定 | 内容 |
|------|------|
| PRD | F-11 智能填充；F-01 人机快速开桌；§9 无账号 |
| 页面 | `lb_scr_home` / `lb_scr_lobby` |
| UI id | `lb_cmp_nick_field` · `lb_btn_quickstart` · `lb_cmp_playercount` · `lb_tog_silent` |

### 4.2 演示怎么讲（30 秒）

1. 卸载残留或清一次数据后的「首次」：点昵称框，系统智能填充弹出建议名，选一条。  
2. 开一局（可秒退）。  
3. 再进建桌：点「常用配置」或二次进入自动带出 **4 人 / 3 命 / 静默关**（或上次值）。  
4. 旁白：「没有登录，但第二次开桌不用重填。」

### 4.3 实现要点（选型级）

| 要点 | 约定 |
|------|------|
| 昵称 | `lb_cmp_nick_field` 打开智能填充 / Autofill（如合适的 `contentType`）；结果写入 `lb.profile` |
| 常用桌 | **不是**系统密码填充；用 `Preferences` 存 `default_players`/`lives_default`/静默局上次值，UI 提供「一键填上次」 |
| 与配置表 | 一键填只覆盖「开桌选项」，不得覆盖锁定规则键的包内默认（命数可改开桌值，但默认仍来自 JSON） |
| 失败 | 填不出来就空手打字；**不得**弹登录 |

### 4.4 不做清单

- 不做账号、云同步、华为 ID 强制绑定  
- 不填充他人战绩、不填充手牌  
- 不把智能填充做成「自动出牌」（那是 AUTO_PLAY，另一回事）  
- 不收集超出昵称与开桌选项的个人信息  

### 4.5 验收一句

> **无账号前提下，昵称可用系统智能填充；第二次开桌可一键带回上次人数/命数/静默局，3 步内能开始人机局。**

## 5. P1 候补（非 MVP 承诺）

下列可写进「有余力 / 展望页」，**答辩失败不背锅**。若做，仍须服务玩法。

| 特性 | PRD | 30 秒讲法（备忘） | 若做：要点 | 仍不做 |
|------|-----|-------------------|------------|--------|
| 互动卡片 | F-22 | 桌外拉出卡片「牌桌进行中 / 再来一局」 | Form Kit；字段同实况窗三件套 + 胜者 | 不做匹配邀请垃圾卡片 |
| 沉浸光感 | F-23 | 质疑拍 3 桌面/灯效切红 | 氛围光或 UI 爆灯；静默局关闭 | 不做硬件灯必选项 |
| 智感握姿 | F-21 | 单手左握，快捷区改右侧 | 握姿回调只改 UI 锚点 | 不改规则、不替代防窥 |

FaceAR（F-20）是互动增强，不是鸿蒙「必勾」特性；手动轮盘必须可完全替代。

## 6. 为何不选全场景接续 / 3D

| 不选 | 一页纸/PRD 依据 | 技术理由（给答辩） |
|------|-----------------|-------------------|
| 应用接续 / 全场景跨端主流程 | 一页纸 §5 第一条不做 | 要第二台设备与分布式调试；MVP 是 1 真人 3 AI，**主路径不依赖跨端**。接续也不解决手牌防窥或质疑裁定。 |
| 3D 场景 / 3DGS / 空间建模 | 一页纸 §5 | 工期与包体过重；心理博弈看的是牌与脸，不是场景面数。2D 酒馆皮足够。 |
| 碰一碰组队作必选项 | 一页纸 §5 | 人机演示不依赖；可后置。 |
| 语音房 | 一页纸 §5 / PRD P2 | 审核与噪声；文字+表情优先。 |

**对外口径**：我们选的三件都直接对应「看不清我的牌 / 盯得住回合 / 开得起桌」；接续和 3D 好看但不增加一局骗子酒吧的信息量。

## 7. 降级与演示风险

| 风险 | 处理 |
|------|------|
| 实况窗无权益 / 非白名单机 | 桌内倒计时仍在；讲稿改口「端侧已接 Kit，现场降级」 |
| 防窥机型无视角硬件 | 至少截屏为黑/空；侧拍靠 UI 对比 + 隐私模式 |
| 智能填充框不弹 | 本地上次昵称仍在；现场手打不超过 4 字 |
| 静默局 | 三特性仍可用；只关震动/催促音 |

## 8. 给策划共拟（`docs/03-鸿蒙与AI` 待补）

本批 **不代替** 写 `03-鸿蒙与AI/`。下列空位请策划用玩法话术填上，程序只认枚举和触发点。

| # | 需补什么 | 触发点（程序已锁） | 策划应产出 | 不要做成 |
|---|----------|-------------------|------------|----------|
| C1 | 看牌防窥的桌内提示一句 | `lb_scr_peek` 开/关 · `lb_privacy_on` | 教学与首次看牌气泡（可复用 `lb_str_peek_hint`） | 不要写成「系统保证没人看得见」（硬件做不到） |
| C2 | 实况窗三字段的**对外用词** | `TURN` / `CHALLENGE_ONLY` / `JUDGE` 等 | 每阶段 ≤8 字；宣称简称格式（「出 A」vs「本轮 A」） | 不要加牌面、不要加「他在撒谎」 |
| C3 | 被点名时实况窗/短震动文案 | `Play.namedSeatId` 非空 | 「{名}点了你」是否进胶囊（进则仍无牌面） | 不要改质疑规则 |
| C4 | 仅质疑窗（8s）的荷官口头禅 | 进入 `CHALLENGE_ONLY` | 一句催质疑、一句超时跳过 | 不要暗示「必须质疑」 |
| C5 | 重建发牌（一圈无推进）播报 | `REDEAL_STALL` | 荷官模板：不扣命、重新发、谁先出 | 不要说成流局判负 |
| C6 | 智能填充空态/成功态微文案 | `lb_cmp_nick_field`、`lb_btn_quickstart` | 按钮名、失败提示 | 不要引导注册账号 |
| C7 | 静默局与三特性的开关文案 | F-13 | 哪些关（催、震、嘲讽音）、哪些仍开（防窥、实况窗） | 不要静默时关掉防窥 |
| C8 | 答辩 3 分钟里特性插入点 | 教学步 2；锁屏一下；第二次开桌 | 写进演示脚本时间轴 | 不要单独开「特性展览页」当主演示 |
