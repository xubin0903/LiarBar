## 3. 状态机（已拍板）

逻辑名供程序 / 测试对齐。挂在 `lb_scr_table` 的手牌层，**不另开路由**，不升格 `lb_scr_play`（已废）。

```
Idle
  → Peek/Selected
  → MultiSelected
  → ConfirmReady     （合法选中时叠加，与 Peek/Selected 或 MultiSelected 同在）
  → Playing
  → Settle
       ↘ Idle（下一手 / 轮转后）
```

取消（任意选中态，含 ConfirmReady）：

| 操作 | 结果 |
|------|------|
| **点空白** | 全部取消 → Idle（牌落下、翻回牌背） |
| **再点同牌** | 只取消该张；剩余 0 → Idle；剩余 1 → Peek/Selected；剩余 ≥2 → MultiSelected；合法性变了则确认条按 §5 显隐 |

### 3.1 各态定义

| 态 | 进入条件 | 手牌外观 | 确认条 |
|----|----------|----------|--------|
| **Idle** | 默认；取消完毕；Settle 收束 | 牌背、未抬起 | 不出现 |
| **Peek/Selected** | Idle 点 1 张且选中成功 | 该张 **正面 + 抬起**（同动画路径，见 §4） | 合法则叠加 ConfirmReady |
| **MultiSelected** | 已有选中，再成功点入另一张 | 所有已选正面 + 抬起 | 合法则叠加 ConfirmReady |
| **ConfirmReady** | 选中集合 **合法**（§5） | 同 Peek/Selected 或 MultiSelected | **出现** `lb_btn_play_confirm` |
| **Playing** | 点确认（可点态）且提交被引擎接受 | 本手牌离手，入本手扣牌区（牌背对外） | 立刻收起 |
| **Settle** | 引擎已记 PLAY，UI 收束 | 余牌回 Idle 排列 | 不出现 |

`Peek/Selected` 是同一态：第一张被点中，既算翻开（peek）也算选中（selected）。不存在「只翻开未选中」的稳定态。

### 3.2 转移表（测试可抄）

| 从 | 事件 | 到 | 失败则 |
|----|------|----|--------|
| Idle | 点某张，且己回合、有牌可出、未超上限 | Peek/Selected | 非法选，见 §5.2 / §8；停在 Idle |
| Peek/Selected | 点另一张，且未超上限 | MultiSelected | 超额：停在原态 + 短句 |
| Peek/Selected 或 MultiSelected | 再点已选中的那张 | 去掉该张（见上表） | — |
| Peek/Selected 或 MultiSelected | 集合变为合法 | 叠加 ConfirmReady | 非法则条不出现 |
| ConfirmReady | 点 `lb_btn_play_confirm`（可点） | Playing | 未翻面完成 / 合法性被抽走：短句，不进 Playing |
| Playing | 引擎 PLAY 成功 | Settle | 引擎拒收（非己回合等）：回选中态 + 短句 |
| 任一选中态 | 点空白 | Idle | 若残留选中 = 测试失败（§8 F5） |
| 任一选中态 | 回合被切走 / 进入质疑仪式 / 手牌清空 | Idle（条若未收完可短暂 `_disabled`） | 不得在别人回合保持可点确认 |

质疑仪式中：手牌点选 **无效**（与 01「三拍中不允许看牌挡仪式」同口径）。本线不因此解冻质疑。

## 4. 翻转动画（已拍板）

### 4.1 结论（可执行）

**单张 peek 与「选中抬起」走同一动画路径。**  
点牌 = **翻面 + 抬起一次做完**；选中态 **保留抬起与正面**，不再翻回牌背。  
取消选中（再点同牌或点空白）走 **同一路径反向**：落下 + 翻回牌背。

禁止做成「只抬不翻」或选中后自动翻回牌背（那是长按松手，不是本线）。  
与 UI [15 §3](../04-设计/15-局内手牌触摸出牌规格.md)「两条动效串行」的会签口径：**用户感知仍是一次点选走完翻+抬**；实现可把翻/抬收成同一时间轴（总长仍 180～280ms），选中保留抬起/正面。15 的控件 id / 确认条线框仍认，本岗不改 15 像素。

### 4.2 时长与打断

| 项 | 锁 |
|----|----|
| 建议时长 | **220ms**（正向 / 反向同一量级） |
| 允许区间 | **180～280ms**（UI 15 可在此区间内定一值，须全文同一） |
| **连点可打断** | **是。** 新 tap 立即改目标：未完成的翻转不锁输入；从当前姿态插值到新目标，不必播完再响应 |
| 打断例子 | 翻转中再点同牌 → 改为取消（反向）；翻转中点另一张 → 第一张落到选中（或保持已完成姿态），第二张开转 |

### 4.3 与长按揭全手

长按仍用互动方案 §3.2 的揭/收（约 150～200ms，01 已占位），**不是**本条同路径。  
长按揭开时：已点选的牌保持选中抬起；未选中的牌仅在按住期间露正面，松手未选中者回牌背。长按本身不改选中集合。

## 5. 多选上限与合法性

### 5.1 上限公式（对齐 v0.2）

```
MAX_PLAY     = max_play_cards = 3     // 数值表已锁；GDD 称 MAX_PLAY
MIN_PLAY     = min_play_cards = 1
hand_count   = 当前自己手牌张数
cap          = min(MAX_PLAY, hand_count)
legal(n)     = 己回合 且 阶段允许 PLAY 且 hand_count ≥ 1
               且 MIN_PLAY ≤ n ≤ cap
```

- 手牌 5 张：最多选 **3**。  
- 手牌 2 张：最多选 **2**（不是 3）。  
- 手牌 0：不能选；见 §5.2「无手牌仅质疑窗口」。  
- 本线 **不改** `MAX_PLAY` / `MIN_PLAY` / `hand_size_default` / `lives_default`。

### 5.2 非法选 · 失败短句（写死）

点选被拒时：**不进入新选中**，150ms 量级轻抖（01 `_fail`），出下列短句（桌内 Toast / 旁注，不模态）。质疑仍冻，本线只注边界、不扩质疑 UI。

| 情形 | 短句（写死） | key 建议 |
|------|--------------|----------|
| 张数不符 / 超额（再选会超过 `cap`） | 这手最多 {n} 张。 | `lb_str_hand_cap` |
| 非己回合点选手牌 | 还没轮到你。 | `lb_str_hand_not_turn` |
| 无手牌、仅质疑窗口（GDD §10.1） | 没有牌了，只能质疑。 | **复用** `lb_str_hand_empty`（02 / 荷官规格已锁，不改字） |
| 无手牌且不可质疑（自动跳过语境） | 没牌，过。 | 复用荷官 `lb_str_dlr_skip_empty` 语义；桌内可只播荷官句 |
| 质疑仪式进行中点手牌 | （无新句；点选无效、无选中） | 不另造「可以质疑了」类句 |

`{n}` = 当前 `cap`（不是永远写 3）。  
**本线不增加、不重排质疑按钮。** 「只能质疑」只是边界提示，解冻质疑玩法另票。

### 5.3 确认提交与出牌包

**硬路径**：ConfirmReady → 点 `lb_btn_play_confirm` → Playing。  
默认记录：方式 `SOFT`、带话跳过、不点名。张数 = 当前选中集合。牌面仍只自己可见，对外入池为牌背（GDD §6.1）。

与 `lb_sheet_play` / `lb_btn_play`：

- 半屏出牌包（方式 / 带话 / 点名）**仍有效**，本线不废 01/02 已锁 id。  
- **两确认钮不得同时可点**，避免双提交。  
- UI [15](../04-设计/15-局内手牌触摸出牌规格.md) 已把半屏降为次路径；**两确认钮不得同时可点**。  
- **H3 不可砍**。本岗不改 15 半屏像素。

超时仍走 GDD `AUTO_PLAY`（随机 1 张、合法优先真）；若选中态被超时收走，不视为玩家确认。本线不改超时规则。

## 6. 确认条

### 6.1 显隐

| 条件 | 条 |
|------|----|
| 选中集合 **合法**（§5.1 `legal(n)`） | **出现**，按钮可点（`_idle`） |
| 选中非法（0 张、超额未入选、非己回合等） | **不出现**（不是挂一条灰钮） |
| 条已挂出，合法性被抽走（回合切走、进仪式、手牌被清空） | 未收完前可走 `_disabled` + 旁注；收完回不出现 |

「仅合法选中时出现」是显隐锁。禁用态只留给 **条已挂出、提交窗已关** 的瞬时，不是非法选中的常驻样子。

### 6.2 可点态 / 禁用态

| 态 | 后缀 | 视觉（语义，非像素） | 点击 |
|----|------|----------------------|------|
| 可点 | `_idle`（可加 `_press`） | 夜馆主确认皮；文案「出牌」 | 进 Playing |
| 禁用 | `_disabled` | **夜馆禁用皮**（压暗 / 描边收回） | 不提交；可出旁注「还没轮到你。」 |

**禁止用系统默认灰钮当终态视觉。** 占位期也要用项目主按钮禁用态，不能把系统 `Button` 灰块当成交件。

文案 key：复用 `lb_str_play`（「出牌」）。不要口语「骗子酒馆」进按钮。

### 6.3 位置（交互落点，不绑贴底硬修）

**贴底安全区上沿、可点优先**：确认条落在底安全区（inset）**上沿**，保证拇指能点到，不被手牌完全盖住，也不被系统手势条吞掉。

本句 **只锁可点**，不改手牌条高度、不改 11/12 贴底缝 / 环-手 24% / `padB` 禁令。  
横屏手牌贴底硬修 **本轮搁置**；本 PR **不重开**该硬修，不把确认条当成贴底闸的新验收句。  
UI 15 画线框时引用本条语义即可，像素另稿。
