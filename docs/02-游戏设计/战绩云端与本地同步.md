## 0. 裁定（硬锁）

1. **云端为准**：某账号一旦完成同步拉取，该账号的对局历史以云端副本为权威；本地只是该账号的离线缓存与待上报缓冲。
2. **本地按账号区分并保留**：本地 Preferences 按 `lb.auth.auth_username` 分桶；切换账号 / 退出登录**不得**抹掉其他账号的本地桶。退出只清 `lb.auth` 会话（登录 schema §4.1），**不**清任何账号的战绩桶。
3. **本地先写、同步尽力**：结算路径仍走 21 §2.4 `commitOnce`（先落本账号本地桶）；上报云端 best-effort，失败不回滚本地、不挡回大厅 / 结算关页。
4. **同 `matchId` 冲突：云端胜**：拉取合并时，云端已有的 `matchId` 覆盖本地同 id；本地独有且未成功上报的条目进入待上报队列，下次 push 再试。
5. **鉴权同登录**：`Authorization: Bearer <auth_token>`（来自 `lb.auth`）；基址与登录同机（§1.2）。
6. **零新玩法**：质疑入口 / 对局状态机 / 人机 AI / 结算字段语义不动；本页不改 21 正文。
7. **文档岗零 ets**：本 PR 只改本文 + 目录索引一行；`string.json` 键数维持 360。

## 1. 云端 API：拉取 / 上报

### 1.1 字段信封（与 `MatchRecordV1` / `RecordSummaryV1` 对齐）

单局记录字段与 21:260–280 / `RecordStore.MatchRecordV1` **逐字段同名同型**（不多不少）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `v` | number | 恒 `1` |
| `matchId` | string | 引擎 `matchId`；云端 upsert 主键 |
| `endedAt` | number | ms |
| `durationMs` | number | 扣暂停后时长（21 §1.2） |
| `rounds` / `hands` / `playerCount` / `rank` | number | 同 21 §2.2 |
| `result` | `'WIN'` \| `'LOSE'` | 中退恒 LOSE |
| `quit` / `ff` | boolean | 中退 / 快进 |
| `livesLeft` / `plays` / `fakeHands` / `doubts` / `doubtHits` / `doubted` / `caught` | number | 同 21 §2.2 |
| `opponents` | string[] | 对手 `aiPersona`，座位序 |

汇总字段与 21:284–293 / `RecordSummaryV1` 同：

| 字段 | 类型 |
|------|------|
| `v` | `1` |
| `total` / `wins` / `quits` / `doubts` / `doubtHits` | number（全量累计，不受本地 20 条限制） |

### 1.2 基址

与 [登录与本地令牌](./登录与本地令牌.md) §1.2 **同基址**（负责人 2026-10-23 已锁）。

| 项 | 值 |
|----|----|
| 基址 | `http://101.33.196.35:18080` |
| 传输 | HTTP（需 `ohos.permission.INTERNET`，登录客户端已声明） |
| 超时建议 | 连接/读各 **8s**（到点走 fail-soft） |
| 鉴权头 | `Authorization: Bearer <auth_token>`（`lb.auth.auth_token`；非空才发） |

| 动作 | 方法 | 路径（本页锁定，供运维落地） |
|------|------|------------------------------|
| 拉取 | `GET` | `/api/v1/records` |
| 上报（单条或批量 upsert） | `POST` | `/api/v1/records` |

> 账号身份只认 Bearer 令牌对应的服务端用户；**请求体/查询不得另带 username 冒充他人**。

### 1.3 `GET /api/v1/records`（拉取）

**请求**：无 body；可选查询（本阶段可忽略，运维可后加）：

| 查询 | 说明 |
|------|------|
| （无） | 默认返回该账号「面板用 recent + 全量 summary」 |
| `since_ended_at`（可选） | number ms；仅增量。本阶段客户端可不发 |

**成功响应**：

```json
{
  "ok": true,
  "recent": [ { "v": 1, "matchId": "...", "endedAt": 0, "durationMs": 0, "rounds": 0, "hands": 0, "playerCount": 4, "rank": 1, "result": "WIN", "quit": false, "ff": false, "livesLeft": 2, "plays": 3, "fakeHands": 1, "doubts": 1, "doubtHits": 1, "doubted": 0, "caught": 0, "opponents": ["AI_TIMID"] } ],
  "summary": { "v": 1, "total": 12, "wins": 5, "quits": 1, "doubts": 20, "doubtHits": 9 }
}
```

| 字段 | 要求 |
|------|------|
| `ok` | `true` |
| `recent` | 数组；**新在前**；**最多 20 条**（与 21:254 / `RecordStore.KEEP=20` 面板口径一致）；元素须通过与 `RecordStore.validateRecord` 同语义的字段校验 |
| `summary` | 对象；全量累计；须通过与 `parseSummary` 同语义校验（含 `wins+quits≤total` 等） |

云端可内部存 >20 条；**GET 的 `recent` 仍截到 20**。客户端面板只吃这 20 + summary。

### 1.4 `POST /api/v1/records`（上报 upsert）

**请求体**（单条或批量；至少提供一种）：

```json
{
  "records": [
    { "v": 1, "matchId": "m1", "endedAt": 1, "durationMs": 1, "rounds": 1, "hands": 1, "playerCount": 4, "rank": 2, "result": "LOSE", "quit": false, "ff": false, "livesLeft": 0, "plays": 2, "fakeHands": 0, "doubts": 0, "doubtHits": 0, "doubted": 1, "caught": 0, "opponents": ["AI_BOLD", "AI_TIMID", "AI_RANDOM"] }
  ]
}
```

| 规则 | 说明 |
|------|------|
| upsert 键 | `matchId` |
| 已存在 | **云端胜**：忽略本次 body 中同 id 字段（或整条丢弃）；响应标明 skipped |
| 不存在 | 写入；服务端更新该账号 `summary` |
| 演示局 | 客户端**不得**上报（21 §2.4 / §4.4；`commitOnce` 本就不写） |
| 非法条 | 跳过该条，其余继续；对应 `REC_VALIDATION` 可附 `rejected` |

**成功响应**：

```json
{
  "ok": true,
  "accepted": ["m1"],
  "skipped": [],
  "rejected": [],
  "summary": { "v": 1, "total": 13, "wins": 5, "quits": 1, "doubts": 20, "doubtHits": 9 }
}
```

`summary` 为上报后服务端权威汇总（客户端可选用其刷新本地该账号 summary）。

### 1.5 错误响应

统一建议信封（字段名可跟运维 OpenAPI，语义须可对下表）：

```json
{
  "ok": false,
  "code": "REC_UNAUTHORIZED",
  "message": "未登录或令牌失效"
}
```

| `code`（建议） | 场景 | 客户端行为 |
|----------------|------|------------|
| `REC_UNAUTHORIZED` | 缺/坏 Bearer；令牌失效 | 不改本地桶；§5 `lb_str_records_sync_unauthorized`；**本阶段不强制踢登**（另票若加 `/me` 再锁） |
| `REC_VALIDATION` | 字段非法 / `v≠1` / 自洽失败 | 该批或该条失败；本地保留；§5 `lb_str_records_sync_bad_payload` |
| `REC_RATE_LIMIT` | 限流 | 退避重试；§5 `lb_str_records_sync_rate_limit` |
| （无 body / 非 JSON） | 坏包 | §5 `lb_str_records_sync_bad_response` |

HTTP / 传输层：

| 情况 | 行为 |
|------|------|
| 无网 / 超时 | 提示（可静默日志 + 可选 Toast）；**不崩**；本地桶不动；待上报保留；§5 `lb_str_records_sync_network` |
| HTTP 非 2xx | 有 `code` 对上表；无 `code` 时按状态映射（401→UNAUTHORIZED，400→VALIDATION，429→RATE_LIMIT）；本地不回滚 |
| `ok!=true` | 当失败；本地不回滚 |

### 1.6 流程摘要（接线顺序）

1. **结算 / 中退**：现有路径 `RecordStore.commitOnce` → **只写当前账号本地桶**（§2）→ 返回是否写入。
2. **若 `commitOnce` 真写入且已登录**：异步 `POST /api/v1/records` 上报该条；失败入待上报；不阻塞 UI。
3. **登录成功 / 冷启动已登录进大厅后（idle）**：`GET /api/v1/records` → §3 合并规则刷本地该账号桶 → 可选再 flush 待上报。
4. **未登录**：不发 records API；若本阶段强制登录已锁，大厅不可达，本条为防御。
5. **禁止**：无令牌写云端；用本地伪造汇总覆盖云端；退出时清空其他账号桶。

## 2. 本地 Preferences 边界（相对现网 `RecordStore`）

### 2.1 现网（本 schema 合入前 · 只读描述）

对照 `RecordStore.ets` / 21:254–257：

| 项 | 现网 |
|----|------|
| 命名空间 | `PersistNs.RECORDS` = `lb.records` |
| 键 | `recent_v1` / `summary_v1` / `last_match_id`（**未按账号分桶**） |
| 写入 | `commitOnce`：去重 `last_match_id`、演示跳过、最多 20、汇总累加、`flush()` |
| 读容错 | 21 §2.6 / `loadFrom`：坏条丢弃、汇总重算、读时不写盘 |

登录 schema §4.1 已写：退出**不清** `lb.records`。在「单桶共享」现状下，换账号会看到上一账号战绩——**本页要改掉这一点（接线 PR）**。

### 2.2 目标本地形态（接线 PR 实现）

| 项 | 口径 |
|----|------|
| 命名空间 | 仍用 `lb.records`（少动 `PersistNs`） |
| 分桶键前缀 | `u:<auth_username>:` + 原键名 |
| 例 | `u:player01:recent_v1` · `u:player01:summary_v1` · `u:player01:last_match_id` · `u:player01:pending_push_v1` |
| `pending_push_v1` | JSON 数组；待上报的 `MatchRecordV1[]`（新在前或按 `endedAt`）；成功从队列剔除 |
| 当前会话 | `RecordStore` 内存只加载**当前** `auth_username` 的桶；无用户名（防御）→ 不读写任何 `u:` 键、不 commit |
| 退出 / 切换 | 只切内存指向；**磁盘上其他 `u:*` 键一律保留** |
| 写后 | 必须 `flush()`（同 21:254） |

### 2.3 迁移（一次性，接线 PR）

若磁盘仍存在无前缀旧键 `recent_v1` / `summary_v1` / `last_match_id`：

1. 当前已登录且 `auth_username` 非空 → 搬到 `u:<username>:*`，然后删除旧键（或搬完标 `migrated_v1=1` 再删）。
2. 未登录遇到旧键 → **不动**（等下次登录再搬）；不丢数据。
3. 禁止把旧键复制到多个账号。

### 2.4 与 `commitOnce` 的边界（写死）

| 步骤 | 谁做 | 失败 |
|------|------|------|
| 1. 校验 snap / 去重 / 演示跳过 / 组 `MatchRecordV1` | 本地 `RecordStore`（语义同现网） | 同现网：返回 false，不上报 |
| 2. 写入当前账号 `recent`/`summary`/`last_match_id` + `flush` | 本地 | persist fail-soft；仍可尝试入 `pending_push`（实现可选；建议：本地 flush 成功才入队） |
| 3. `POST` 上报 | 同步层（新模块或 `RecordStore` 旁路） | 入 / 留 `pending_push`；§5 网络短句可只打日志 |
| 4. 拉取合并 | 同步层 | 本地桶保持拉取前状态 |

**结算面板 / RECAP / 中退路径不因同步失败而改变 21 §2.4 写入时机。**

## 3. 合并与冲突（云端胜）

对**当前账号**桶，一次成功 `GET` 后：

1. 校验云端 `recent` / `summary`；任一侧整包非法 → 当失败，本地不动（§1.5）。
2. 建集合 `cloudIds` = 云端 recent 的 `matchId`。
3. 本地 recent 中：`matchId ∈ cloudIds` → **丢弃本地条（云端胜）**；`matchId ∉ cloudIds` → 视为未上报，**保留并确保进入 `pending_push`**。
4. 展示用 recent = 云端 `recent`（已 ≤20，新在前）∪ 本地独有条，再按 `endedAt` 降序截断到 20（本地独有不得把云端权威条挤出显示时可优先保留云端条——**已锁：先铺云端 recent，再追加本地独有，总长截 20**）。
5. `summary`：**采用云端 `summary`** 为权威；本地独有未上报条对汇总的贡献在 push 成功前可以「显示值 = 云端 summary + 本地独有折算」或「仅显示云端、角标稍后同步」——**本阶段锁：面板 summary 显示 = 云端 summary + 对本地独有条的增量折算（wins/quits/doubts/doubtHits/total）**；push 成功后再被下次 GET 的权威 summary 覆盖。
6. `last_match_id`：取合并后 recent[0].matchId（无则空）；不得因合并写坏导致后续 `commitOnce` 崩（对齐 21 §2.6）。
7. 合并结果写回当前账号键并 `flush()`。

跨设备同一账号：后拉取者吃云端；未上报本地独有通过 pending push 汇入，随后云端胜收敛。

## 5. 失败短句（看什么 / 算不过）

本 PR 不改 `string.json`（当前 **360** 键）。键名接线 PR 再 ADD。

| 场景 | 看什么 / 算不过 | 建议键 |
|------|-----------------|--------|
| 无网/超时 | 看什么：本地战绩仍在、可进面板；算不过：闪退或清空桶 | `lb_str_records_sync_network` |
| 未授权/令牌失效 | 看什么：不同步、本地保留；算不过：误清空本地或假同步成功 | `lb_str_records_sync_unauthorized` |
| 坏响应 | 看什么：当失败；算不过：用半包覆盖本地 | `lb_str_records_sync_bad_response` |
| 载荷校验失败 | 看什么：该条不上云、本地仍在；算不过：整桶被清空 | `lb_str_records_sync_bad_payload` |
| 限流 | 看什么：稍后重试；算不过：狂刷打爆 | `lb_str_records_sync_rate_limit` |
| 换账号串桶 | 看什么：B 账号看不到 A 的 recent；算不过：退出/登录后仍显示他号战绩 | `lb_str_records_account_leak` |
| 退出误清他号 | 看什么：A 退出后 A 的 `u:A:*` 仍在盘；算不过：退出删光 `lb.records` | `lb_str_records_logout_wipe` |
| 云端胜未生效 | 看什么：同 matchId 以云端字段为准；算不过：本地脏条盖住云端 | `lb_str_records_cloud_override_fail` |
| 同步挡结算 | 看什么：关结算/回大厅不因 sync 挂起；算不过：等 POST 才关页 | `lb_str_records_sync_blocks_ui` |
