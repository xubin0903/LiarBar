## 0.1 与美术命名关系（已锁）

两套 ID **并存，不要互相改名**：

| 层 | 前缀 | 谁定 | 例子 | 谁用 |
|----|------|------|------|------|
| 媒体文件 | `art_*` | 美术 [关键资源规格清单.md](./关键资源规格清单.md)（**PR#4**；未合入 `develop` 时以该 PR 为准） | `art_card_a.png` | DevEco `$r('app.media.art_card_a')` |
| 屏幕 / 路由 | `lb_scr_*` | UI（本文 §2） | `lb_scr_table` | 路由 / 埋点 / 测试 |
| 组件 | `lb_cmp_*` | UI（本文 §4） | `lb_cmp_hand` | 组件 `.id` / 自动化 |
| 按钮 / 操作点 | `lb_btn_*` | UI（本文 §4） | `lb_btn_challenge` | 同上 |

**硬规则**：

- 控件 = `lb_*`。媒体 = `art_*`。
- **禁止**再写 `lb_art_*`（双前缀已废；旧稿 §5 槽位表作废）。
- 色值、尺寸、导出文件名以美术清单为准；本文只写 **`lb_*` → `art_*` 映射**，不另发明媒体名。
- 风格问题走 `feat/art-*`；改控件 id 走 `feat/ui-*`，两边改完回填清单对照表。

## 1. 统一前缀与分段（仅 `lb_*` 控件）

```
lb_<类别>_<对象>[_<变体>][_<状态>]
```

| 段 | 取值 | 例 |
|----|------|----|
| 前缀 | 固定 `lb_` | `lb_` |
| 类别 | `scr` 屏幕 · `cmp` 组件 · `btn` 按钮 · `ico` 图标控件 · `tog` 开关 · `txt` 文本 · `sfx`/`hpt` 调用点 · `slot` 空位 · `sheet`/`cover` 容器 | `lb_btn_` |
| 对象 | 小写蛇形，英文语义 | `quickstart` `challenge` |
| 变体 | 可选：座位、花色、拍号 | `p1` `soft` |
| 状态 | 见 §3（控件态，不是文件名） | `_idle` `_press` |

**`art` 不是 `lb_` 下的类别。** 媒体不用 `lb_` 前缀，文件名直接用美术 `art_*`。

其它规则：

- 全小写 + 下划线；不用驼峰、不中文 id。
- 同一控件所有态 **共享主名**，只换后缀。
- 逻辑枚举（`SOFT` / `KNOCK` / `SMILE`）保持与互动方案一致；对应媒体是 `art_play_soft` / `art_sign_knock` / `art_emote_smile`，不是 `lb_art_*`。
- 禁止第三套前缀（不要 `liar_` / `xh_` / `ui_`）。`art_*` 是已锁的媒体层，不算第三套。

## 3. 状态后缀（控件层）

用于 `lb_*` 的可见态 / 程序态。媒体若有独立 PNG，**文件名变体以美术清单为准**（如 `art_ai_timid_hold`），不要把控件后缀抄成 `lb_art_*`。

### 3.1 通用交互

| 后缀 | 含义 | 谁必须实现（控件） |
|------|------|-------------------|
| `_idle` | 默认可点 / 默认可显示 | 所有可点 `lb_btn_*` / `lb_cmp_*` |
| `_press` | 按下未抬起 | 所有 `lb_btn_*`、可点牌 |
| `_disabled` | 不可用 | 质疑（第一手）、超选牌、次数用尽的方式 |
| `_on` / `_off` | 开关 | 静默局、AI 补位 Toggle |
| `_selected` | 多选/芯片选中 | 手牌、方式、带话、点名、押注 |
| `_success` | 动作被接受 | 出牌提交、入座完成（可选，用动画代替也行） |
| `_fail` | 动作被拒 | 非法点击的轻抖；可不单独出图 |
| `_empty` | 空态 | 手牌 0、战报表 0 |
| `_timeout` | 超时代打/跳过 | 出牌包收起、仅质疑窗结束 |

### 3.2 胜负与生命

| 后缀 | 含义 |
|------|------|
| `_win` | 本局胜 / 本次质疑赢 |
| `_lose` | 本局负 / 本次质疑输 |
| `_life_3` `_life_2` `_life_1` `_life_0` | 命点（0 = 出局/幽灵） |
| `_ghost` | 幽灵旁观外观 |
| `_turn` | 当前行动座位描边 |
| `_called` | 被点名 |
| `_signed_ok` / `_signed_no` | 被画 ✓ / ✗ |

### 3.3 质疑四拍（全岗锁名 · 不是 `_challenge_*` 后缀）

程序态用 **全名** `lb_challenge_*`（与工程 PR#7 一致）。口播可仍说「起势→揭牌→结果」。

| 锁名 id | 口播 | 互动方案 | 用在 |
|---------|------|----------|------|
| `lb_challenge_windup` | 起势 | 拍1 指控 | `lb_cover_challenge`、`lb_btn_pose_*` |
| `lb_challenge_standoff` | （对峙） | 拍2 对峙 + 押注 | `lb_cmp_bet_bar`、反应面具 |
| `lb_challenge_reveal` | 揭牌 | 拍3 翻牌 | `lb_cmp_reveal_row` / `lb_cmp_reveal_card_*` |
| `lb_challenge_result` | 结果 | 定格 | 破防/死撑、假牌描边；可叠 `_win` / `_lose` |

跳过仪式：切到 `lb_challenge_result`（或直接 `JUDGE`）。全屏切红用 **程序 overlay**（美术清单 §6）。

### 3.4 出牌方式（控件后缀）

| 控件后缀 | 枚举 | 挂上的媒体（美术清单） |
|----------|------|------------------------|
| `_soft` | SOFT | `art_play_soft` |
| `_slam` | SLAM | `art_play_slam` |
| `_hesitate` | HESITATE | `art_play_hesitate` |

P1 的 `_pin` / `_blind` 对应 `art_play_pin` / `art_play_blind`（清单已列）。**MVP 不进面板。**
