## 1. 三态优先级（所有本表控件）

| 优先级 | 态 | 谁触发 | 视觉 | 音频 |
|--------|-----|--------|------|------|
| 最高 | **pressed** | 指针按下 / 手指 `TouchType.Down` | 沿用 #27 §E 的 scale；盖过 hover | CTA / peek 仍走 `lb_sfx_cta_tap`（静默关） |
| 中 | **hover 或 focus** | 鼠标进入 **或** 键盘 / TV / 无障碍焦点 | **铜边或高光闪**（#32 R2）；示意「可点」 | **无**。悬停出击打音 = R2 不过 |
| 低 | **idle** | 离开且失焦 | 回 #27 §F.2 稳态（主 CTA 微光；peek / 设置卡不动） | — |

重叠规则：

1. **pressed > hover/focus > idle 微光**。按下时不要叠出「悬停 × 按下」。scale **一律相对 idle 基准 1.0**。  
2. **悬停主信号是铜边 / 高光，不是再放大。** #32 H2：只用按钮 `scale` 冒充悬停 = 不过。若叠 scale，全程 **≤1.01**（与 §F.2 微光同帽）。因此悬停必须 **靠边或高光** 才能比微光更强、可辨。  
3. 主 CTA 进入 hover / focus 时：**压过或暂停** v3 §3.4 稳态微光（4.0～5.0s、`opacity 0.92↔1.00`、scale ≤1.01）。悬停高光 Δ 须 **≥0.15**（#32），不能和微光糊成同一种呼吸。  
4. **移入 / 获焦（P1）**：**1 帧内**（≤16ms）金边或高光必须已经能读出「可点」。禁止用 `animateTo({ duration: 80～120 })` 当到达。#32 的 80～120ms 只留给 **离开 / 失焦收回**（建议 100～120ms，与 #27 `BOOT_MS_CTA_RELEASE` 同窗）。不要拖成 300ms+。  
5. 静默局（`lb_tog_silent == on`，**P4**）：**悬停 / 焦点动效仍在**；**无击打音**（hover 本来就不该出 sfx；按下亦关 `lb_sfx_cta_tap`、无强震）。

## 2. `lb_btn_quickstart`（主 CTA）

对照 #32 §3.2 + #27 §E / §F.2。热区高 ≥56vp；独立于设置卡（03 已锁）。

| 态 | 视觉 | 时长 | 音频 | 禁止 |
|----|------|------|------|------|
| hover | **金边闪 / 高光**（R2 主信号）：`tavern_accent` `#F0C14B` 或 `tavern_brass` `#C4A46A` 描边 / 外发光；**或** 高光层相对常态 **Δ ≥ 0.15**。可选叠 `scale ≤ 1.01`，**不能只靠 scale** | **移入 1 帧内**（≤16ms）已能看出可点；离开 **100～120ms** 回 idle | **无**（P4） | 等长动画才亮；只放大当悬停；1.04+；整屏闪白；和 §3.4 微光同幅度 |
| focus | **与 hover 同级、等价可感知（P3）**：至少 2vp `tavern_accent` / brass 焦点环。获焦同样 **1 帧内**亮 | 同左 | **无**（P4） | 只做系统默认蓝环、在褐底上看不见；只做 PC hover |
| pressed | **保持** #27 / **P2**：`scale 1→0.96`，按下 **≤80ms**；抬起 **100～120ms** 回 1 | 同 #27 | `lb_sfx_cta_tap` ≤80ms（**静默关**，P4） | 改数字、用按压冒充悬停 |
| idle | #27 §F.2 稳态微光：4.0～5.0s，高光 `0.92↔1.00` 或铜边极弱；**scale 峰值 ≤1.01** | 入场 stagger 结束后才开 | 无周期性 UI 音 | 悬停时仍叠微光抢同一条弱呼吸 |

实现提示：hover 用「金边 + 高光」；微光让路。**第一帧先切到亮态**（改 `border` / 高光 opacity），不要把「可点」绑在 80～120ms `animateTo` 上。不要把 §F.2 的 1.01 呼吸再加大到 1.02 当交差——#32 已把悬停 scale 帽死在 1.01，**可见差靠边和 Δopacity**。

## 5. 真机兜底（必做 · 不能只做鼠标）

真机 / 多数模拟器 **没有稳定 mouse hover**。只写 `.onHover` = 验收失败（**P3**；#32 R2a 已写「无键鼠时把焦点落到该钮」）。`focus` / `pressed` 必须与 PC hover **等价可感知**（同一套金边 / 高光或按压缩放，不能弱到看不出来）。

| 输入 | 必须看见 | ArkUI 提示（会签后落 `feat/client-*`，本 PR 不写） |
|------|----------|--------------------------------------------------|
| PC 鼠标 | hover 闪 / 高亮 | `.onHover((isHover: boolean) => { ... })`，有指针时走 §2～§4 hover |
| 键盘 / TV 遥控 / 无障碍焦点 | **focus 环** | `.focusable(true)`；`.onFocus` / `.onBlur` 走与 hover **同级或略强** 的焦点样式。主 CTA、peek、静默开关、昵称框、填上次（若在）都要能吃到焦点 |
| 手机手指 | **pressed** 仍示意可点 | 主 CTA / peek **已有** `.onTouch` 按压缩放（#27 §E），保持。设置卡开关 / 输入 / 弱链补同等可见 press 或 focus，禁止死静态 |
| 模拟器 | 有鼠标走 hover；无鼠标走 focus 或 press | 两条路径都要过；不能写「模拟器没 hover 就算了」 |

层级：

```
有指针 → hover 样式（铜边 / 高光）
有焦点 → focus 样式（可与 hover 共用同一套「可点」高亮）
按下   → pressed（#27 数字，盖过上两者）
都没有 → idle（主 CTA 仅稳态微光；其余不动）
```

**不要**依赖「用户会先用鼠标滑过才知道能点」。手机上第一次接触就该是 press 反馈。

ArkUI：**先改态再可选收回动画**。移入 / 获焦用瞬时切描边或高光（`duration: 0` 或 ≤16ms），满足 P1；**不要** `animateTo({ duration: 80～120 })` 当「亮起来」。离开 / 失焦才用 100～120ms EaseOut 收回。不要新控件、不要 `lb_btn_hover_*`。
