## 1. 结算战报（`lb_scr_report`）

### 1.1 进入条件

| 来源 | 条件 | 结算形态 |
|------|------|----------|
| 正常终局 | `collectRedeal()` 内 `aliveCount ≤ 1` → `toRecap()` | 完整战报 |

### 1.3 新增引擎私有日志 `playLog`（结算唯一数据源）

`eventLog` 公共事件不写牌面（GDD §7.2）；结算需要「这一手是否掺假 / 是否被拆穿」，故引擎新增**私有**数组，局中不出现在快照，只在 RECAP 后用于结算。

| 字段 | 类型 | 写入点 |
|------|------|--------|
| `seq` | number，1 起，= 本局手序 | `commitPicked()` 追加时 = `playLog.length + 1` |
| `round` | number | `roundIndex` |
| `actorSeatId` | number | `commitPicked()` |
| `count` | 1～3（张数） | `commitPicked()` |
| `fakeCount` | number | `commitPicked()` 内已算的 `fake` |
| `style` | SOFT / SLAM / HESITATE | `commitPicked()` 的 `style` 参数（已含 SLAM/HESITATE 限次降级） |
| `challenged` | boolean | `applyJudged()` 置 true |
| `challengerSeatId` | number，默认 −1 | `applyJudged()` |
| `caught` | boolean（裁定 SUCCESS） | `applyJudged()` |
| `loserSeatId` | number，默认 −1 | `applyJudged()` 的 `loser` |

写死：

1. `applyJudged()` 时 `lastPlay` / `challenge` 仍有效，**在这里写入** = 「在 `collectRedeal()` 清空 `challenge` / `lastPlay`（MatchEngine.ets:645-648）之前快照」。结算一律读 `playLog`，**禁止**在 `toRecap()` 里再读 `snap.lastPlay` / `snap.challenge`（此时已为 null → 高光半空 S21-25）。
2. `rollbackLastPlay()` 必须同步弹出 `playLog` 末条；`seq` 不留空号。**禁止**用 `playId` 里的 `playSeq` 当手序（rollback 不回退 `playSeq`，会跳号）。
3. `startMatch()` 清空 `playLog`；`collectRedeal()` / `dealFresh()` **不清**。

### 1.4 三个高光 + 回放句

对齐 GDD §12「最大连骗、最准质疑、最惨连熄」。三卡固定顺序、固定徽章。展开 / 收成 / 回放行只认 §1.4.3a 兜底三条，不得三层叠说同一件事。

#### 1.4.1 H1 最大连骗（`art_hl_long_bluff`）

| 项 | 定义 |
|----|------|
| 数据 | `playLog` |
| 算法 | 对每座 s，按 `seq` 顺序遍历其出牌：`fakeCount>0 且 caught=false` → `run+=1`，`best[s]=max(best[s],run)`；否则（真牌手，或被拆穿的假手）`run=0` |
| 入选 | `best ≥ 2` |
| 并列 | ① `best` 大者 ② 该段 `fakeCount` 之和大者 ③ 该段末手 `seq` 小者（先达成） |
| 文案 | `lb_str_hl_bluff_fmt`：{昵称}=该座，{k}=`best` |
| 降级 | 无人 ≥2 → `lb_str_hl_bluff_none`（仅 §1.4.3a 规则 1：另有高光入选、三卡仍展开时） |

注：未被质疑的掺假手（含 RoundSafeWait 封存手）算骗成功。局后公开是否掺假不违反 GDD §9.3（该条只管局中）。

#### 1.4.2 H2 最准质疑（`art_hl_best_challenge`）

| 项 | 定义 |
|----|------|
| 数据 | `challengeHits[]` / `challengeCounts[]` |
| 算法 | `h = challengeHits[s]`，`k = challengeCounts[s]` |
| 入选 | `h ≥ 1` |
| 并列 | ① `h` 大者 ② 命中率 `h/k` 高者 ③ 第 h 次命中的 `seq` 小者（先达成） |
| 文案 | `lb_str_hl_doubt_fmt`：{昵称}，{k}，{h} |
| 降级 | 全桌 `h=0` → `lb_str_hl_doubt_none`（仅 §1.4.3a 规则 1：另有高光入选、三卡仍展开时） |

#### 1.4.3 H3 最惨连熄（`art_hl_worst_break`）

| 项 | 定义 |
|----|------|
| 数据 | `eventLog` 中 `LIFE_CHANGE`（每条 = 一次 PenaltyExtinguish1）与 `OUT` |
| 算法 | 按事件顺序取 `LIFE_CHANGE` 的 `seatId` 序列；对每座求「连续相同 seatId」的最长段长 `k`（中间无他座熄烛） |
| 入选 | `k ≥ 2`（上限 3） |
| 并列 | ① `k` 大者 ② 以该座 `OUT` 收尾者 ③ 人类座 ④ 段首事件早者 |
| 文案 | 收尾出局 → `lb_str_hl_burn_out_fmt`；否则 `lb_str_hl_burn_fmt`；{昵称}，{k} |
| 降级 | 无人 ≥2 → `lb_str_hl_burn_none`（仅 §1.4.3a 规则 1：另有高光入选、三卡仍展开时） |

注：`debugDecLife()` 也写 `LIFE_CHANGE`；交付包无该入口，不特判。

#### 1.4.3a 兜底三条（写死 · 负责人打回 2026-10-07）

单卡降级句、整区兜底句、回放行不可叠说同一件事。只认下面三条（S21-46）：

| # | 条件 | 显示 |
|---|------|------|
| 1 | 三条高光**至少一条入选** | 三卡照常都在；未入选的卡各走本卡降级句：`lb_str_hl_bluff_none` / `lb_str_hl_doubt_none` / `lb_str_hl_burn_none` |
| 2 | 三条**都不入选** | 三卡收成**一句**：整局未判过质疑（含开局即中退）→ `lb_str_hl_none`=「这一局，没人掀过牌。」；有过质疑但都未达门槛 → `lb_str_hl_quiet`=「这一局，没有谁特别出挑。」本卡降级句**不出现**。禁止退回胜者行「{胜者} 留下。」 |
| 3 | 回放句无靶 | **整行隐藏**（不写句）。已裁定的质疑必有靶，故规则 2 的 quiet 案回放句照常显示 |

#### 1.4.4 回放句（GDD §12「动作回放一句」，替换现 `buildHighlight()`）

| 步 | 规则 |
|----|------|
| 选靶 | ① `playLog` 中最后一条 `challenged=true` 且（`actorSeatId` 或 `challengerSeatId` = 人类座）② 否则最后一条 `challenged=true` ③ 否则无靶 |
| 选模板 | `caught=true` 且挑战者=人类 → `lb_str_replay_hit_fmt`；`caught=true` 其它 → `lb_str_replay_caught_fmt`；`caught=false` → `lb_str_replay_wrong_fmt`；无靶 → **整行隐藏**（§1.4.3a 规则 3） |
| 占位 | {被质疑者}=`actorSeatId` 昵称；{质疑者}=`challengerSeatId` 昵称；{手}=`seq`；{方式}=`style` → `lb_str_style_word_*` |

#### 1.4.5 `{n}` 与 `{手}` 语义（写死）

| 占位 | 语义 | 用在 |
|------|------|------|
| `{n}` | **张数** = `lastPlay.count`（1～3） | DealerLines 局中句：`lb_str_dlr_play` / `_play_named`（「出了 {n} 张」） |

### 1.5 名次与淘汰顺序

名次（出局与中退同一公式）= 「出局那一刻还活着的座数（含自己）」；胜者 = 1。4 人桌例：最先出局 = 4，第二 = 3，第三 = 2，胜者 = 1。

| 情况 | 名次 |
|------|------|
| 胜者 | 1 |
| 出局座 | 「出局那一刻还活着的座数（含自己）」 |
| 中退人类（D1 · 已拍板 2026-10-07） | 同出局公式；视作此刻出局；其余存活座名次显示「—」 |
| 快进局 | 同正常终局（快进不改规则，名次真实） |

### 1.7 出局选择（L3）

| 项 | 规则 |
|----|------|
| 触发 | 人类座 `lives→0`（`OUT`）且熄烛序列放完、`aliveCount ≥ 2` |
| 不触发 | 人类出局即终局（只剩 1 存活）→ 直接进结算 |
| 期间 | 弹层期间按暂停处理（§3 PAUSED 子态 `ELIM_CHOICE`），AI 不动 |
| 直接看结算（D2 · 已拍板 2026-10-07） | 快进：导演用虚拟时钟连续 `pulse()`，`DEAL` 直接 `dealDone()`、仪式 `skipRitual()`、`PENALTY` 直接 `penaltyDone()`，无音频、无动画，直到 `RECAP`。步数上限 `FF_MAX_STEPS=4000`；超限回落为「继续观战」并记日志 `ff_cap` |

### 2.6 存档容错

- `lb.records` 单条明细解析失败或字段不合法（含 `v` 缺失/不认识）→ 只丢弃这一条，其余照常显示；不崩、不弹错。

| 音乐（BGM 轨） | 0～100，步进 5，默认 **100** | `vol_bgm` | `LobbyAudio`（`bgm_lobby_night`、`lb_sfx_amb_tavern` 环境床）、`TableAudio` 局内 BGM |
| 音效与语音（SFX 轨） | 0～100，步进 5，默认 **100** | `vol_sfx` | `TableAudio` 全部 SFX、`SoundPlayer`（翻牌 / 熄烛）、`DealAudio`、`LobbyAudio` 的 SFX（环境床除外）与 `lb_vo_*` |
| 静音（总开关） | 开 / 关，默认关 | `mute_all` | 四类音频全部静音；**不改滑条值**（S21-23） |
| 规则说明 | — | — | 打开 §5 面板 |
| 关于 | — | — | 显示 `lb_str_set_about_body`、版本行、授权行 |
| 答辩演示 | 默认关 | **不持久化**（内存态；杀进程即清） | **仅大厅**设置 → 关于（连点版本 7 次）；**局内设置不出现**；只对下一局（§4.4） |

写死：

1. 乘子层：实际音量 = 代码常量（`VOL_*`）× `vol/100`；`mute_all` 开时乘子 = 0。默认 100 = 现有听感不变。
2. 拖动中：循环床（BGM / amb）实时跟随；一次性 SFX 下一记生效（S21-22）。
3. 松手：写 Preferences 并 `flush()`；同时试听一记（大厅 `lb_sfx_cta_tap`，局内 `lb_sfx_turn_tick`，仅 SFX 滑条）。
4. 冷启动先读 `lb.settings` 再起大厅 BGM（S21-21）。
5. **静音 ≠ 静默局**：大厅 `lb_tog_silent`（静默局，GDD §10：关催促抖动 / 嘲讽音 / 强弹幕，按局生效）保留不动。音频是否出声 = `!mute_all && !(局内 && silentMode)`。局内且静默局时设置面板显示 `lb_str_set_silent_match_note`，滑条仍可改。
